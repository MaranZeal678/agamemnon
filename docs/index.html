The problem

Authorized does not mean safe.

In 2026, researchers recorded at least nine cases where an AI agent deleted a company's live data on its own. Every time, the agent was allowed to do it, so no monitoring tool ever flagged it. The dashboards stayed green while the database emptied. The root cause is simple: the agent holds the password and can do anything with it.

With Agamemnon

The same agent. No password. Blocked in seconds.

Now the agent holds no database credential at all. It reasons its way to the exact same mistake, but this time the delete is only a request. Agamemnon measures the real size with its own access: 412,000 rows, not the 1,210 the agent believed. Plain rules block it, an operator sees exactly why, and the board never moves.

And when a real change is needed

Approve the reasonable ones. Undo the mistakes.

A genuine 900-row cleanup looks reasonable, so Agamemnon holds it for a person to approve. Approve it and the rows really are deleted. If it turns out to be wrong, one click restores them in seconds, because Agamemnon backed up the exact rows before deleting, and the undo is recorded as its own reviewed action.

How it works

Every change becomes a reviewed request.

01

Written down first

The request and its audit record are saved together, so there is always a paper trail.

02

Measured for real

Agamemnon counts, with its own access, exactly how many rows would change — not the agent's guess.

03

Checked by plain rules

Readable rules decide allow, needs-approval, or block. The AI opinion can only make it stricter.

04

Backed up before deleting

The exact rows are saved first, so anything can be undone in seconds.

05

Run with a one-time key

The delete uses a key minted for that single action, then thrown away.
